# scrudful 0.6: DRF parity for object validators, 201 validators, list envelope and error bodies — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `scrudful.rest_framework` the `scrudful.ninja` features that django-scoped-rbac needs for DRF/ninja parity, and add a hook for the body of scrudful's own 400/412/428 responses. Release the result as scrudful **0.6.0**.

**Architecture:**
- The page slicing and URL logic that `ninja.py` keeps private moves into framework-neutral `scrudful/collection.py`.
- The DRF adapter gains three opt-in features:
  - validators computed from the object `view.get_object()` returns (after DRF's queryset filtering and object permissions);
  - validators and `Location` on 201;
  - a `ScrudfulPagination` class that produces the same scrud list envelope as `scrudful_list`.
- A new `error_body_func` option on all adapters lets an application replace the body of scrudful's early 400/412/428 responses.
- `scrudful.problem.problem_details` is a ready-made RFC 9457 body for it.

Every new behaviour is opt-in, so existing DRF users see no change (#2's note).

**Tech Stack:** Python ≥3.10, Django ≥4.2, DRF ≥3.15, django-ninja ≥1.7,<2, FastAPI ≥0.100, pytest (+pytest-django, pytest-randomly, `filterwarnings = ["error"]`).

**Spec:** `~/dev/django-scoped-rbac/docs/superpowers/specs/2026-10-25-semantic-http-drf-ninja-design.md`, section 0. scrudful issue #2 (`https://gitlab.com/dcharbon/scrudful/-/work_items/2`). Reference implementation: `scrudful/ninja.py` and `docs/source/ninja.rst`.

**Sequence:** This is plan 2 of 3. django-scoped-rbac's plan 3 depends on the 0.6.0 release.

- Branch `feat/drf-parity-0.6` from `master` in `~/dev/scrudful`. One MR to `master`. Bump with `uv version 0.6.0` in the MR (`version-check` requires a bump).
- **Opt-in only.** With none of the new options set, every existing test passes unchanged, and every existing DRF response is byte-for-byte the same.

- Envelope wire shape is fixed by `collection.py`'s `PAGE_FIELDS` (`count`, `page_count`, `first`, `previous`, `next`, `last`, `content`) and `ENVELOPE_FIELDS` (`href`, `etag`, `last_modified`, `link`, `content`). DRF must produce the identical JSON that `scrudful_list` produces for the same items, URLs and callbacks.
- Pagination parameters are `page` (≥1, default 1) and `page_size` (≥1, default 100, at most 1000), as `scrudful_list` uses. A page past the last answers 404 with the body `{"detail": "Invalid page."}`, and page 1 always exists.
- CHANGELOG heading `0.6.0 (since 0.5.0)`, themed `---` subsections, `*` bullets, issues as `(#2)`.
- Creating GitLab issues or posting comments is outward-facing. **Ask the owner first** (task 6).

## Review Focus

1. **Object validators with a missing object.** `get_object()` raising `Http404` must give the view's normal 404 (through DRF's exception handling, with error Links if configured), never a 412/428. Task 2 test `test_object_validators_missing_object_is_404_not_428`.
2. **Object validators with an object the user may not see.** The callbacks must never run, and no `ETag` may leak on the 403/404. Task 2 test `test_object_validators_not_called_when_permission_denied`.
3. **`get_object()` called once per request.** Preconditions, the handler and the post-write refresh must not re-query in a way that sees a different object, and the handler must receive the same instance. Task 2 test `test_handler_reuses_the_precondition_object`.
4. **An unordered queryset in the DRF envelope.** It must warn the same way as ninja, and with `filterwarnings=error` the test must assert the warning. Task 4 test `test_pagination_warns_on_unordered_queryset`.
5. **A 428 body rewritten by `error_body_func`.** It must keep `Content-Type` equal to the error entity's media type and keep the `accepted-precondition-headers` information. Task 5 test `test_error_body_func_keeps_428_accepted_headers`.

### Task 2: DRF object validators (scrudful#2 item 1)

**Files:**
- Modify: `scrudful/rest_framework.py` (`ScrudfulViewFunc.__init__`/`_handle`, `scrudful`, `scrudful_viewset`, `_VALIDATOR_OPTIONS`)
- Test: `tests/test_rest_framework_object_validators.py` (new, with its own URLconf via `pytestmark = [pytest.mark.urls(__name__), pytest.mark.django_db]`, like `tests/test_rest_framework.py`)

**Interfaces:**
- New option `object_validators: bool = False`. It is a keyword on `ScrudfulViewFunc`/`scrudful`, and a `Meta.object_validators` read by `scrudful_viewset`, applying to the item actions `retrieve`, `update`, `partial_update`, `destroy`. With it set:
  - Before preconditions: `obj = view.get_object()`. An exception propagates as the view's own would (DRF handles 404/403, with no validators computed).
  - `etag_func(obj)` / `last_modified_func(obj)` take **the object only**, as in ninja.
  - `evaluate_preconditions(..., exists=True)`.
  - The handler's own `get_object()` returns that same instance for this request. `scrudful_viewset` wraps the class's `get_object` with a per-request memo stored on the request under a private attribute.
  - After a 2xx PUT/PATCH, the memo is cleared and `view.get_object()` is called again for the fresh validators, mirroring ninja's second `load`. If that raises `Http404`/`PermissionDenied`, send no validators.
- `scrudful_api_view(..., object_validators=True)` raises `TypeError("object_validators needs a view with get_object()")` at decoration time.
- `object_validators=True` without `etag_func`/`last_modified_func` raises `TypeError` at decoration (mirrors ninja's `load` rule, inverted).

### Task 4: DRF list envelope, `ScrudfulPagination`

**Files:**
- Modify: `scrudful/rest_framework.py` (new `ScrudfulPagination`, exported in `__all__`; `scrudful_viewset` reads `Meta.href_func`)
- Test: `tests/test_rest_framework_envelope.py` (new)
- Modify: `docs/source/usage.rst` (DRF section), `README.rst` (DRF snippet mentions it)

**Interfaces:**
- `class ScrudfulPagination(rest_framework.pagination.BasePagination)`:
  - `page_size = 100`, `max_page_size = 1000`, `page_query_param = "page"`, `page_size_query_param = "page_size"`.
  - `paginate_queryset(self, queryset, request, view=None) -> list`. It uses `collection.slice_page`, maps `InvalidPage` to `NotFound("Invalid page.")`, and raises `ValidationError({"page_size": [...]})` (400) for a non-integer, `<1` or `>max_page_size` value, and the same for `page`.
  - `get_paginated_response(self, data) -> Response`, which returns `collection.page_envelope(...)` whose entries are `collection.envelope_entry(href=..., etag=..., last_modified=..., link=..., content=item_data)`.
    - `href` comes from `view`'s `Meta.href_func(view, request, obj)`. It is required, and a missing one raises `ImproperlyConfigured` at first use.
    - `etag`/`last_modified` come from the item callbacks with `object_validators` semantics (`func(obj)`). They are `None` when the callbacks are absent, and `last_modified` is formatted with `format_http_date`.
    - `link` is `join_links(*_entity_links(item entity, ...))`.
  - `get_paginated_response_schema(self, schema)` returns `collection.collection_schema`'s shape, for DRF's OpenAPI.
- It pairs objects with serialized `data` by index: `paginate_queryset` keeps the page's objects on `self`.

### Task 5: `error_body_func` and `scrudful.problem.problem_details`

**Files:**
- Create: `scrudful/problem.py`
- Modify:
  - `scrudful/rest_framework.py` (`ScrudfulViewFunc`, `scrudful`, `scrudful_api_view`, `Meta.error_body_func`, `_conditional_response`)
  - `scrudful/ninja.py` (`scrudful`, `scrudful_create`, `scrudful_list`, `_early_response`)
  - `scrudful/fastapi.py` (the decorator's early response)
- Test: `tests/test_error_body.py` (new; one test per adapter per status)

**Interfaces:**
- Option `error_body_func: Callable[[Any, ConditionalResult], dict[str, Any]] | None = None` on every decorator (DRF also as `Meta.error_body_func`).
  - It is called as `error_body_func(request, result)` for an early 400/412/428 (never for 304).
  - Its return value replaces `result.body`. Status, headers, Links and `Content-Type` are unchanged.
- `scrudful.problem.problem_details(request, result: ConditionalResult) -> dict[str, Any]` returns RFC 9457 members:
  - `{"type": "about:blank", "title": reason_phrase(result.status), "status": result.status, "detail": result.body["detail"]}`;
  - plus every other key of `result.body` as an extension member (so `accepted-precondition-headers` survives).
- `scrudful.problem.PROBLEM_JSON = "application/problem+json"`. An `Entity(media_type=PROBLEM_JSON, ...)` is already accepted as an error entity (it is `+json`).
